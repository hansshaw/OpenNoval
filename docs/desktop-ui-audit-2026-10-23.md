# 桌面外观优化与代码审计记录

日期：2026-10-23。平台：Linux x64；开发 Node.js 26.9.0、Go 1.27.3；桌面 Electron 44.9.0。

## 交付内容

- 默认保留原始深色静态界面，新增水墨、清爽、暧昧和原神灵感四套完整配色。
- 侧栏、导航、概览、表单、阅读器、模型设置、媒体模块、弹窗和反馈统一使用主题颜色；主要文字在六类基础表面上的对比度不低于 4.5:1（禁用控件不计入）。
- 四幅原创 SVG 随 Go embed 分发；无需外部图片、字体、网络请求或第三方素材授权。
- 外观面板使用原生 dialog、单选框和开关，支持键盘选择、Escape 关闭和焦点恢复。
- 流光由用户独立开启，仅覆盖装饰区域和顶栏边缘，装饰不接收指针事件；系统减少动态效果时禁用播放，隐藏窗口时暂停。
- SQLite 持久化主题和动效；localStorage 仅作为快速缓存。迟到的启动读取不会覆盖新选择，连续写入串行，保存失败可见且可重试。
- 换肤不重载页面，不触发模型请求，不修改作品数据或创作风格引用。

## 审计范围与修复

审计结合源码追踪、独立复审、已有全流程测试和新增回归测试，重点覆盖并发、数据持久化、用户草稿、模型凭证和桌面隔离。

| 范围 | 已确认的问题 | 修复与回归验证 |
| --- | --- | --- |
| 状态刷新 | 较早发出的请求较晚返回，会覆盖新的审批和批次状态 | 单调请求序号与项目 epoch 联合过滤过期状态及错误 |
| 中文输入 | 输入法 Enter 选字可能提交故事；快捷键可能绕过禁用按钮 | 检查 composition、229 键码和按钮状态 |
| 章节编辑 | 保存过程中切换章节，原章节缓存未确认新 revision，返回后再次保存冲突 | 更新发起保存时捕获的草稿，保留其他未保存字段及后续编辑 |
| 共创草稿 | 后台事件强制刷新会清除 dirty 状态，覆盖手改的创作原则 | 显式确认、重置或切换项目之前保留 dirty 草稿 |
| 项目写入 | 未持有 Host 时，资料编辑、归档和清空共创可能绕过其他实例的作品锁 | 获取并校验租约与删除标记；重建 Host 前释放临时租约 |
| TXT/EPUB 导出 | 导出逐文件读取时可与恢复、编辑、删除交错，产生不一致内容 | 闲置项目在快照锁内导出；前端同步禁用忙碌目标的导出按钮，其他项目仍可运行 |
| 模型列表发现 | 跨来源重定向可能携带 API Key，尤其是 x-api-key | 仅允许原协议、主机和端口上的重定向，并限制跳转次数 |
| 断点日志 | 缺换行的尾记录会与下次追加拼接；失败写入可能造成序号重用 | 严格检查 JSONL 尾行与递增正序号；不确定写入重试前重新读取并同步磁盘 |
| 导出错误 | 目录解析失败被吞掉，导出丢失章名或卷结构却显示成功 | 将目录解析错误返回用户；同时覆盖 TXT 与 EPUB |

断点日志发现损坏后明确报错并停止追加，不自动删改原始记录。修复旨在防止继续破坏数据，不承诺自动修复已经损坏的历史文件。

## 验证边界

所有模型交互使用本地确定性 mock，没有读取真实用户模型配置或调用付费 API。现有业务流程通过测试不代表真实模型的文学质量已验证；图片、视频与语音生成仍是现有产品尚未实现的扩展能力。本次验证 Linux x64，未运行 Windows 原生安装与视觉验收。对比度测试验证主题基础颜色，截图另外检查实际排版；不宣称穷尽所有数据组合或第三方服务行为。

# 提示词缓存与成本控制

本项目通过模型连接与角色配置使用提供商支持的提示词缓存。
协议转换位于模型适配层，角色请求身份由创作运行时维护；工作台展示
实际请求、输入输出 Token 与服务端返回的使用量，不把缓存命中当作必然结果。

## 本项目的边界

- 同一作品的稳定设定和规则尽量保持请求前缀稳定。
- 不同作品、角色与风格蒸馏任务独立组织上下文，避免跨作品污染。
- 正文或规划修改后，后续请求使用已保存的新内容。
- 缓存行为取决于提供商、模型、协议与连接参数；不保证所有兼容接口支持。
- API Key 保留在本机配置。日志与界面请求记录应使用脱敏结果。

维护代码时从 `internal/bootstrap/` 的模型配置、`internal/llmcontract/`
的调用约束和 `internal/modelrequest/` 的请求记录入手。
角色与上下文组织见 [上下文管理](context-management.md)。

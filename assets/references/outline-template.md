# 大纲规划模板

本模板的作用不是把所有作品都压成固定长度，而是帮助先判断作品级别，再选择大纲粒度。

## 第一步：先判断作品长度级别

### 短篇 / 单卷故事

- 适用：单冲突、单目标、角色少、结局集中
- 参考长度：8-25 章
- 建议格式：扁平 `outline`

### 中篇 / 多阶段故事

- 适用：有阶段升级、数条支线、人物关系会变化
- 参考长度：25-60 章
- 建议格式：扁平 `outline` 或轻量分层

### 长篇连载 / 网文型故事

- 适用：题材天然具备持续升级空间、长期关系张力、多个阶段目标、可扩展世界、长期谜团或长期成长线
- 参考长度：80-200+ 章
- 建议格式：分层 `layered_outline`

## 第二步：判断是否必须使用分层大纲

只要满足下面任意 2 条，就优先使用 `layered_outline`：

- 世界观需要逐步展开，而不是一次性讲完
- 主角成长不是一次跃迁，而是多阶段升级
- 人物关系会在多个阶段持续变化
- 中期和后期存在不同类型的主矛盾
- 需要多次地图/势力/身份/目标切换
- 题材明显更像连载型商业小说，而不是单卷故事

## 第三步：长篇时不要直接做“全书章节流水账”

长篇规划顺序建议是：

1. 作品卖点与差异化
2. 长期故事引擎
3. 卷级主题与升级
4. 弧级目标与阶段转折
5. 章节级事件与钩子

错误做法：

- 先写 20 章梗概，再强行拉长
- 每卷都重复“遇敌-变强-换地图”
- 只有主线升级，没有关系升级
- 前期把所有大秘密透支完，中后期只能重复套路

## 扁平大纲模板（短/中篇）

```json
[
  {
    "title": "章节标题",
    "core_event": "本章核心事件",
    "hook": "章末钩子",
    "scenes": ["场景1", "场景2", "场景3"]
  }
]
```

## 分层大纲模板（长篇 - 完整卷弧规划）

长篇使用卷、弧、章三级结构。新规划的完整范围必须一次落盘：每个卷都有弧，每个弧都有真实章节；不得保留空卷、空弧或只有 `estimated_chapters` 的骨架。

```json
[
  {
    "title": "第一卷标题",
    "theme": "这一卷新增的核心矛盾/主题",
    "arcs": [
      {
        "title": "第一弧",
        "goal": "局部目标、阻力和转折",
        "chapters": [
          {"title": "章节标题", "core_event": "核心事件", "hook": "章末钩子", "scenes": ["场景1", "场景2"]},
          {"title": "章节标题", "core_event": "核心事件", "hook": "章末钩子", "scenes": ["场景1", "场景2"]}
        ]
      },
      {
        "title": "第二弧",
        "goal": "这一弧的局部目标、阻力和转折",
        "chapters": [
          {"title": "章节标题", "core_event": "核心事件", "hook": "章末钩子", "scenes": ["场景1", "场景2"]},
          {"title": "章节标题", "core_event": "核心事件", "hook": "章末钩子", "scenes": ["场景1", "场景2"]}
        ]
      }
    ]
  },
  {
    "title": "第二卷标题",
    "theme": "第二卷主题",
    "arcs": [
      {
        "title": "弧标题",
        "goal": "弧目标",
        "chapters": [
          {"title": "章节标题", "core_event": "核心事件", "hook": "章末钩子", "scenes": ["场景1", "场景2"]}
        ]
      },
      {
        "title": "弧标题",
        "goal": "弧目标",
        "chapters": [
          {"title": "章节标题", "core_event": "核心事件", "hook": "章末钩子", "scenes": ["场景1", "场景2"]}
        ]
      }
    ]
  },
  {
    "title": "第三卷标题",
    "theme": "第三卷主题方向",
    "final": true,
    "arcs": [
      {
        "title": "收官弧",
        "goal": "收束长线并回答终局命题",
        "chapters": [
          {"title": "章节标题", "core_event": "核心事件", "hook": "章末钩子", "scenes": ["场景1", "场景2"]}
        ]
      }
    ]
  }
]
```

- 用户明确卷数、弧数或章节数时，模板结构按其要求增减，不能固定套用示例数量
- “共/正好 N 章”必须让全部实际章节总数严格等于 N；“N-M 章 / 约 N 章 / N 章左右”按区间或合理近似执行
- 用户未明确时，按题材和目标篇幅自主决定完整规模，但所有规划内容都要一次写全
- 卷序号、弧序号和章节序号均由系统按数组顺序生成，不要在 JSON 中提供
- 完整规划只把最后一卷标记为 `"final": true`，表示当前规划故事的终点
- 旧项目若仍含骨架弧，只作为历史兼容逐弧展开；新规划和正常续卷不得再产生骨架弧

## 长篇卷级检查清单

每一卷都要回答：

- 这一卷新增了什么世界信息？
- 这一卷升级了什么核心矛盾？
- 这一卷让主角得到什么，也失去什么？
- 这一卷如何改变主要人物关系？
- 这一卷结束后，故事为什么必须进入下一卷？

## 长篇弧级检查清单

每一弧都要回答：

- 这条弧的明确目标是什么？
- 阻力来自谁、什么规则、什么代价？
- 转折点是什么？
- 这条弧结束后，哪些状态发生了不可逆变化？

## 章节级检查清单

- 每章必须服务于所在弧的目标
- 每章必须包含一个不可删除的事件推进
- 钩子要多样化，不要全靠“发现秘密”一种模式
- 前期章节不能只是在“介绍世界”，必须同步推进人物和冲突
